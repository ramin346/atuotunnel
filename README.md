# BackPack Smart Tunnel Manager

ربات تلگرام برای ساخت و مدیریت تانل معکوس BackPack بین سرور ایران و سرور خارج. برای اتصال یک سرور ایران به چند مقصد، برای هر سرور خارج یک تانل مستقل با پورت کنترل و پورت‌های ورودی مجزا بسازید.

## نصب ربات

کنترلر به Linux با systemd، Python 3.10+، Git، OpenSSH و دسترسی به GitHub و API تلگرام نیاز دارد. هر دو سرور تانل باید Linux با systemd و Python 3.10+ باشند. نصب خودکار موتور BackPack v2.0.0 روی amd64 و arm64 انجام می‌شود و چک‌سام فایل قبل از نصب بررسی می‌شود.

```bash
git clone https://github.com/ramin346/atuotunnel.git
cd atuotunnel
sudo bash install.sh
sudoedit /etc/atuotunnel-bot.env
```

در فایل محیط، `BOT_TOKEN` را با توکن BotFather و `BOT_ADMIN_IDS` را با شناسه‌های عددی مدیران (جداشده با ویرگول) پر کنید. ربات فقط در چت خصوصی به این مدیران پاسخ می‌دهد.

روی کنترلر، برای حساب `atuotunnel` کلید SSH اختصاصی در مسیر `/var/lib/atuotunnel/.ssh/` بسازید. کلید عمومی را روی هر دو سرور مجاز کنید و کلید میزبان هر سرور را پس از تطبیق اثرانگشت از مسیر مستقل، در `/var/lib/atuotunnel/.ssh/known_hosts` ثبت کنید. برای پورت SSH غیراستاندارد، قالب OpenSSH برای نام میزبان `[IP]:PORT` است. حساب SSH روی سرور مقصد باید root یا دارای `sudo -n` برای اجرای مدیریت موتور باشد. مکالمهٔ تلگرام فقط IP، پورت و نام کاربری را دریافت می‌کند.

```bash
sudo systemctl start atuotunnel-bot
sudo journalctl -u atuotunnel-bot -f
```

روی سرور ایران، پورت کنترل TCP را برای اتصال از سرور خارج باز کنید. پورت‌های ورودی را برای کاربران مجاز باز کنید. ربات فایروال، SSH و تنظیمات Xray/V2Ray را تغییر نمی‌دهد. سرویس مقصد باید روی loopback سرور خارج، یعنی `127.0.0.1` یا همهٔ رابط‌های IPv4، در حال گوش دادن باشد.

## نمونهٔ کار

```text
/server ir 192.0.2.10 22 root
/server de 198.51.100.10 22 root
/new xray ir de 3080
/ports xray 443,8443,2053:3000
/test xray
/install xray
/status xray
/repair xray on
```

هر تانل حداکثر ۱۶ نگاشت TCP می‌پذیرد. `2053:3000` یعنی ورودی ۲۰۵۳ ایران به مقصد ۳۰۰۰ خارج می‌رود. `/ports` فهرست کامل نگاشت‌های پیش‌نویس را جایگزین می‌کند. قبل از نصب، تداخل پورت‌های ورودی، پورت کنترل و SSH بررسی می‌شود. برای تأیید دستی، نتیجهٔ `/test` را ببینید و سپس `/install` را بزنید. `/test xray auto` پس از انتخاب روش، نصب را هم انجام می‌دهد.

آزمون با تونل موقت و سرویس echo اجرا می‌شود. برای هر روش سه نمونهٔ ۶۴ کیبی‌بایتی در هر جهت ارسال می‌شود و هر سرویس موقت حداکثر ۷۵ ثانیه فعال است. تعداد نمونه‌های موفق اولویت دارد و در تساوی، میانهٔ زمان رفت‌وبرگشت داده تعیین‌کننده است. عدد Mbps نرخ تقریبی نمونه است و نسبت نمونه‌های ناموفق معادل افت بستهٔ شبکه نیست. آزمون به‌ترتیب `tcp`، `tcpmux`، `ws`، `wsmux`، `wss` و `wssmux` را بررسی می‌کند. سقف دادهٔ آزمون برای هر شش روش ۲٫۲۵ مِبی‌بایت، به‌علاوهٔ سربار پروتکل، است. هنگام ویرایش تانل فعال ممکن است تست با پورت کنترل موقت انجام شود. در آن حالت فایروال باید اتصال سرور خارج به آن پورت را هم مجاز کند.

پس از نصب، اتصال کانال کنترل موتور و دسترسی TCP به ورودی‌های ایران و سرویس‌های مقصد خارج بررسی می‌شود. این بررسی handshake اختصاصی پروتکل Xray/V2Ray را انجام نمی‌دهد. قبل از تغییر، نسخهٔ پشتیبان واحد systemd و TOML مدیریت‌شده ذخیره می‌شود. خطای نصب باعث بازگردانی روی هر دو سرور می‌شود. `/rollback xray` نسخهٔ قبلی را دستی بازیابی می‌کند. اگر SSH قطع شده باشد، پس از بازیابی دسترسی `/recover` را اجرا کنید.

`/license issue DAYS`، `/license list`، `/license assign TUNNEL CODE` و `/license revoke CODE` برای مدیریت لایسنس‌های محلی هستند. لایسنس اختیاری است و اعتبار کد تخصیص‌یافته هنگام نصب و تعمیر خودکار بررسی می‌شود. لغو لایسنس تانل در حال اجرا را متوقف نمی‌کند.

## به‌روزرسانی از داخل تلگرام

پس از ادغام تغییرات در شاخهٔ `main`، در چت خصوصی ربات بنویسید:

```text
/update
```

ربات آخرین کامیت مخزن را دریافت می‌کند، فایل‌های پایتون را پیش از نصب بررسی می‌کند و فقط در صورت امکان به‌روزرسانی fast-forward، کد را جایگزین می‌کند. systemd فرایند را دوباره بالا می‌آورد و ربات شناسهٔ نسخهٔ جدید را گزارش می‌دهد. فایل محیط، وضعیت ربات و پیکربندی تانل‌ها بیرون از checkout نگهداری می‌شوند. این دستور کد ربات را به‌روزرسانی می‌کند. تغییر واحد systemd نیازمند اجرای دوبارهٔ `install.sh` و راه‌اندازی مجدد سرویس است.

```text
/serverlist
/tunnels
/help
```
