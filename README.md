# BackPack Smart Tunnel Manager

ربات تلگرام برای ساخت و مدیریت تانل معکوس BackPack بین سرور ایران و سرور خارج. برای اتصال یک سرور ایران به چند مقصد، برای هر سرور خارج یک تانل مستقل با پورت کنترل و پورت‌های ورودی مجزا بسازید.

## نصب ربات

کنترلر به Linux با systemd، Python 3.10+، Git، OpenSSH و دسترسی به GitHub و API تلگرام نیاز دارد. هر دو سرور تانل باید Linux با systemd و Python 3.10+ باشند. نصب خودکار موتور BackPack v2.0.0 روی amd64 و arm64 انجام می‌شود و چک‌سام فایل قبل از نصب بررسی می‌شود.

```bash
git clone https://github.com/ramin346/atuotunnel.git
cd atuotunnel
sudo bash install.sh
sudoedit /etc/atuotunnel-bot.env
```

در فایل محیط، `BOT_TOKEN` را با توکن BotFather و `BOT_ADMIN_IDS` را با شناسه‌های عددی مدیران (جداشده با ویرگول) پر کنید. ربات در چت خصوصی برای همه منوی دکمه‌های شیشه‌ای دارد. صدور و لغو لایسنس، تعیین دسترسی و به‌روزرسانی برای مدیران فعال‌اند. کاربر دارای لایسنس هم می‌تواند سرورهای خودش را ثبت کند.

ربات هنگام ثبت سرور، کلید میزبان ناشناخته را در اولین اتصال به‌صورت خودکار در `known_hosts` حساب `atuotunnel` ذخیره می‌کند. برای سرور جدید وارد کردن دستی اثرانگشت لازم نیست. این روش در اتصال اول به کلید ارائه‌شده اعتماد می‌کند و اتصال بعدی را در صورت تغییر کلید رد می‌کند. اگر عمداً کلید میزبان را عوض کردید، مدیر باید ورودی قبلی را پس از بررسی کلید جدید به‌روزرسانی کند. حساب SSH روی سرور مقصد باید root یا دارای `sudo -n` برای اجرای مدیریت موتور باشد.

در چت خصوصی، دکمهٔ «ثبت سرور» را بزنید. ابتدا IP را وارد کنید. برای پورت غیراستاندارد از `IP:PORT` یا `[IPv6]:PORT` استفاده کنید. ربات سپس نام کاربری و رمز SSH را جداگانه می‌پرسد. بعد از آزمون اتصال، نتیجه و نام سرور را اعلام می‌کند. `/server NAME` همان فرم را با نام دلخواه باز می‌کند و `/cancel` فرم را می‌بندد.

رمز از طریق چت خصوصی تلگرام به ربات می‌رسد. ربات برای حذف پیام رمز تلاش می‌کند و رمز را جدا از فایل وضعیت، در `/var/lib/atuotunnel/ssh-credentials/` با دسترسی حساب سرویس ذخیره می‌کند. مدیر می‌تواند در مرحلهٔ رمز `/key` بزند و از کلید SSH ازپیش‌تنظیم‌شده برای حساب `atuotunnel` استفاده کند. در این حالت، کلید عمومی حساب سرویس باید روی سرور مقصد مجاز شده باشد. ثبت سرور شخصی کاربران با رمز همان سرور انجام می‌شود.

```bash
sudo systemctl start atuotunnel-bot
sudo journalctl -u atuotunnel-bot -f
```

روی سرور ایران، پورت کنترل TCP را برای اتصال از سرور خارج باز کنید. پورت‌های ورودی را برای کاربران مجاز باز کنید. ربات فایروال، SSH و تنظیمات Xray/V2Ray را تغییر نمی‌دهد. سرویس مقصد باید روی loopback سرور خارج، یعنی `127.0.0.1` یا همهٔ رابط‌های IPv4، در حال گوش دادن باشد.

## نمونهٔ کار

در منوی شیشه‌ای «ایجاد تانل» را بزنید یا `/new` را بدون آرگومان بفرستید. سرور ایران و خارج را از فهرست نام و IP انتخاب کنید، نام تانل را بفرستید و پورت کنترل را تعیین کنید. پورت کنترل برای اتصال سرور خارج به سرور ایران است. اگر ۳۰۸۰ آزاد است، می‌توانید آن را با دکمه انتخاب کنید. پس از ثبت پیش‌نویس، به «مدیریت پورت‌ها» بروید تا پورت‌های ورودی سرویس را مشخص کنید.

```text
/server ir 192.0.2.10 22 root
/server de 198.51.100.10 22 root
/new xray ir de 3080
/ports xray 443,8443,2053:3000
/test xray
/install xray
/status xray
/repair xray on
```

هر تانل حداکثر ۱۶ نگاشت TCP می‌پذیرد. `2053:3000` یعنی ورودی ۲۰۵۳ ایران به مقصد ۳۰۰۰ خارج می‌رود. `/ports` فهرست کامل نگاشت‌های پیش‌نویس را جایگزین می‌کند. قبل از نصب، تداخل پورت‌های ورودی، پورت کنترل و SSH بررسی می‌شود. برای تأیید دستی، نتیجهٔ `/test` را ببینید و سپس `/install` را بزنید. `/test xray auto` پس از انتخاب روش، نصب را هم انجام می‌دهد.

آزمون با تونل موقت و سرویس echo اجرا می‌شود. برای هر روش سه نمونهٔ ۶۴ کیبی‌بایتی در هر جهت ارسال می‌شود و هر سرویس موقت حداکثر ۷۵ ثانیه فعال است. تعداد نمونه‌های موفق اولویت دارد و در تساوی، میانهٔ زمان رفت‌وبرگشت داده تعیین‌کننده است. عدد Mbps نرخ تقریبی نمونه است و نسبت نمونه‌های ناموفق معادل افت بستهٔ شبکه نیست. آزمون به‌ترتیب `tcp`، `tcpmux`، `ws`، `wsmux`، `wss` و `wssmux` را بررسی می‌کند. سقف دادهٔ آزمون برای هر شش روش ۲٫۲۵ مِبی‌بایت، به‌علاوهٔ سربار پروتکل، است. هنگام ویرایش تانل فعال ممکن است تست با پورت کنترل موقت انجام شود. در آن حالت فایروال باید اتصال سرور خارج به آن پورت را هم مجاز کند.

پس از نصب، اتصال کانال کنترل موتور و دسترسی TCP به ورودی‌های ایران و سرویس‌های مقصد خارج بررسی می‌شود. این بررسی handshake اختصاصی پروتکل Xray/V2Ray را انجام نمی‌دهد. قبل از تغییر، نسخهٔ پشتیبان واحد systemd و TOML مدیریت‌شده ذخیره می‌شود. خطای نصب باعث بازگردانی روی هر دو سرور می‌شود. `/rollback xray` نسخهٔ قبلی را دستی بازیابی می‌کند. اگر SSH قطع شده باشد، پس از بازیابی دسترسی `/recover` را اجرا کنید.

## دسترسی کاربران و لایسنس

۱. کاربر در چت خصوصی `/start` می‌زند و شناسهٔ عددی‌اش را برای مدیر می‌فرستد.
۲. مدیر با `/license issue 30` یک کد صادر می‌کند. برای اختصاص سرورهای ثبت‌شده از `/grant USER_ID ir de` استفاده می‌کند. این فرمان فهرست قبلی سرورهای مجاز آن حساب را جایگزین می‌کند.
۳. کاربر از دکمهٔ «فعال‌سازی لایسنس» یا `/activate CODE` استفاده می‌کند. کد به اولین حسابی که آن را فعال کند اختصاص می‌یابد. سپس کاربر می‌تواند از منوی شیشه‌ای با سرورهای شخصی یا اختصاص‌یافته تانل بسازد.

کاربران پیش‌نویس‌ها، تانل‌ها و پیکربندی‌های مستقل دارند. دسترسی به یک سرور به کاربر مجوز تعریف نگاشت پورت برای آن سرور می‌دهد. فقط سرورهایی را اختصاص دهید که کاربر مجاز به انتشار سرویس‌هایشان است. مدیران می‌توانند بدون فعال‌سازی لایسنس تانل‌های خود را مدیریت کنند.

دستورهای مدیر شامل `/license list` و `/license revoke CODE` هستند. انقضا و لغو، عملیات ساخت، تست، نصب، تعمیر و بازگردانی کاربر را مسدود می‌کنند. یک تانل در حال اجرا با این تغییر متوقف نمی‌شود. برای تکمیل بازگردانی معوق کاربری که SSH او قطع شده، مدیر پس از بازیابی دسترسی می‌تواند `/recover USER_ID` را اجرا کند. منوی مدیر و کاربر با `/start` باز می‌شود.

## به‌روزرسانی از داخل تلگرام

پس از ادغام تغییرات در شاخهٔ `main`، در چت خصوصی ربات بنویسید:

```text
/update
```

ربات آخرین کامیت مخزن را دریافت می‌کند، فایل‌های پایتون را پیش از نصب بررسی می‌کند و فقط در صورت امکان به‌روزرسانی fast-forward، کد را جایگزین می‌کند. systemd فرایند را دوباره بالا می‌آورد و ربات شناسهٔ نسخهٔ جدید را گزارش می‌دهد. فایل محیط، وضعیت ربات و پیکربندی تانل‌ها بیرون از checkout نگهداری می‌شوند. این دستور کد ربات را به‌روزرسانی می‌کند. تغییر واحد systemd نیازمند اجرای دوبارهٔ `install.sh` و راه‌اندازی مجدد سرویس است.

```text
/serverlist
/tunnels
/help
```
